## What is Bloocks?

Bloocks is the design system behind the **AI Accountant** products. It holds the design tokens,
foundations and React components used to build its screens, and every value in it comes from the
[AIA Component Library](https://www.figma.com/design/j6l3kRxBQRNGbf3cwR9NZq/AIA---Component-Library?node-id=54-178)
in Figma.

## 🚧 Status

* Bloocks is under **active development**. Components are added as product screens need them.
* Every component in the sidebar has a docs page with live stories, controls and a props table.
* Some token pages are still waiting on Figma. [Elevation](?path=/docs/token-elevation--docs) has one shadow so far, for floating panels.
* Use the **Theme** switch in the toolbar to see any page in light or dark.

## ✨ Features

* **Light and dark themes** from one set of semantic tokens, with no theme logic in components
* **Tokens synced from Figma** and rendered live from `src/styles/tokens.css`, so the docs can't drift
* **Accessible building blocks** on [Radix](https://www.radix-ui.com/primitives) primitives, checked with Storybook's a11y addon
* **Tailwind CSS 4** styling with typed variants from `class-variance-authority`
* **shadcn/ui compatible**. Its variables map onto Bloocks tokens in `src/styles/tailwind.css`
* **Data-heavy screens covered** with a TanStack table, column customizer, filters and date ranges

## 🎨 How tokens are layered

Tokens come in three layers, and each layer only uses the one below it.

```
--palette-blue-500          1. Palette: raw brand values from Figma
        ↓
--color-primary             2. Semantic: a role, swapped per theme
        ↓
bg-[var(--color-primary)]   3. Component: only uses semantic tokens
```

> 🎯 Components use semantic tokens such as `--color-primary` and `--color-text`, never palette tokens such as
> `--palette-blue-500`. That is what makes dark mode work without changing component code.

## 🧩 Using Bloocks

Import the styles once at your app's entry. They include Tailwind and every token.

```tsx
import './styles/tailwind.css'
```

Then import components from their folder:

```tsx
import { Button } from '@/components/Button'
import { Badge } from '@/components/Badge'

<Button variant="outline">Export</Button>
<Badge color="positive">Reconciled</Badge>
```

## 📝 Adding a component

* Create a folder under `src/components` with the component, its variants, a barrel file and stories:

```
src/components/Button/
├── Button.tsx            the component
├── buttonVariants.ts     cva variants, styled with semantic tokens
├── index.ts              public exports
└── Button.stories.tsx    tags: ['autodocs'] creates the docs page
```

* Style only with semantic tokens. If no token fits, add one to `tokens.css` for **both** themes.
* Add the component to `storySort` in `.storybook/preview.tsx` so it shows up in the right place in the sidebar.
* If it uses a new icon, add it to `src/foundations/usedIcons.ts`.
* Add a link to it in the **What's inside** list on this page.
* Run `npm run lint` and check the a11y panel before opening a pull request.

> 🗒 Run Storybook locally with `npm run storybook`. Build a static copy with `npm run build-storybook`.
